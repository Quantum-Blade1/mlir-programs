\chapter{The Five-Pass Progressive Compilation Pipeline}
\label{ch:five_pass_pipeline}

\begin{quote}
\textit{``Compilation is not a monolithic leap from high-level algorithm to hardware pulses; it is an invariant-preserving journey through five progressive transformation stages.''}
\end{quote}

The core execution engine of the DQC compiler is structured as a five-stage progressive optimization pipeline implemented using the MLIR \texttt{PassManager} architecture. Each pass addresses a distinct mathematical and physical abstraction layer, enforcing strict preconditions and yielding formal postconditions. 

This chapter examines the mechanical inner workings of each of the five compilation passes:
\begin{enumerate}
    \item \textbf{Pass 1:} Canonical Ingestion and IR Normalization
    \item \textbf{Pass 2:} Hypergraph Extraction and Balanced Multi-QPU Partitioning
    \item \textbf{Pass 3:} Non-Local Teleportation and Cat-State Synthesis
    \item \textbf{Pass 4:} Coherence-Aware DAG Scheduling and Latency Hiding
    \item \textbf{Pass 5:} Distributed Target Lowering and Runtime Code Generation
\end{enumerate}

\section{Pass 1: Canonical Ingestion and Normalization}
\label{sec:pass1_ingestion}
% ==============================================================================

The ingestion pass parses external input representations (OpenQASM 3.0, QIR bytecode, or high-level algorithm definitions) and emits an unpartitioned monolithic \texttt{dqc} MLIR module.

\subsection{Peephole Algebraic Reductions}
Before partitioning, Pass 1 executes local peephole rewrites to minimize gate depth and eliminate redundant operators. The pass applies standard group-theoretic identities:
\begin{align}
    H \cdot H &\to \mathbb{I}, \quad X \cdot X \to \mathbb{I}, \quad Z \cdot Z \to \mathbb{I}, \\
    R_z(\theta_1) \cdot R_z(\theta_2) &\to R_z(\theta_1 + \theta_2), \\
    \text{CNOT}(c, t) \cdot \text{CNOT}(c, t) &\to \mathbb{I}.
\end{align}

\begin{passbox}{Pass 1 Mechanics}
\textbf{Entry Condition:} Raw quantum circuit AST with arbitrary basis gates.\\
\textbf{Exit Invariants:}
\begin{itemize}
    \item Universal basis reduction: All operations lowered to $\{R_x, R_y, R_z, H, \text{CNOT}, \text{CZ}, \text{Measure}\}$.
    \item Linear SSA verification: Single use of every \texttt{!dqc.qubit} SSA value.
    \item Dead gate elimination completed.
\end{itemize}
\end{passbox}

\section{Pass 2: Hypergraph Extraction and Partitioning}
\label{sec:pass2_partitioning}
% ==============================================================================

Pass 2 transforms the sequential IR into a hypergraph $\mathcal{H} = (\mathcal{V}, \mathcal{E})$ as formalized in Chapter~\ref{ch:hypergraph_partitioning}. 

\subsection{Attribute Attachment}
After KaHyPar computes the balanced partition $\pi: Q \to \{1, \dots, M\}$, Pass 2 decorates every qubit allocation operation with a physical QPU affinity attribute:

\begin{lstlisting}[language=MLIR, caption={Intermediate IR after Pass 2 (QPU Affinity Attached)}]
// Allocations annotated with physical placement attributes
%q0 = dqc.alloc_qubit() {qpu.id = 0 : i32, physical.pin = 4 : i32} : !dqc.qubit
%q1 = dqc.alloc_qubit() {qpu.id = 0 : i32, physical.pin = 5 : i32} : !dqc.qubit
%q2 = dqc.alloc_qubit() {qpu.id = 1 : i32, physical.pin = 2 : i32} : !dqc.qubit
%q3 = dqc.alloc_qubit() {qpu.id = 1 : i32, physical.pin = 3 : i32} : !dqc.qubit

// Gates initially retain monolithic syntax but cross QPU boundaries
%q0_1, %q2_1 = dqc.cnot %q0, %q2 : !dqc.qubit, !dqc.qubit  // CROSS-QPU EDGE!
\end{lstlisting}

\section{Pass 4: Coherence-Aware DAG Scheduling}
\label{sec:pass4_scheduling}
% ==============================================================================

A naive sequential ordering of teleportation operations causes catastrophic decoherence: if an EPR pair is distributed at time $t=0$, but the downstream gate is scheduled at $t = 100\,\mu\text{s}$, the Bell state will have decayed past the classical threshold $F < 2/3$.

Pass 4 constructs a **Dependency DAG** taking into account:
\begin{itemize}
    \item Physical gate execution durations ($\tau_{\text{1Q}} \approx 20\text{ ns}, \tau_{\text{2Q}} \approx 200\text{ ns}, \tau_{\text{meas}} \approx 500\text{ ns}$),
    \item Interconnect EPR generation latency ($\tau_{\text{epr}} \approx 1.5\,\mu\text{s}$), and
    \item Classical inter-refrigerator network round-trip time ($\tau_{\text{class}} \approx 50\text{ ns}$).
\end{itemize}

The scheduler hoists EPR allocation operations so that EPR pairs arrive at the target QPUs precisely when the controlling data qubits enter their execution window, completely eliminating buffer idle time.

% ==============================================================================
\section{Pass 5: Target Lowering and Runtime Generation}
\label{sec:pass5_lowering}
% ==============================================================================

The final pass splits the unified distributed MLIR module into heterogeneous target outputs:
\begin{enumerate}
    \item **Per-QPU Quantum Bytecode:** Emits clean QIR / OpenQASM 3.0 containing only operations local to that QPU.
    \item **Distributed C++ Orchestrator:** Emits an MPI/RDMA runtime driver that handles classical message routing, measurement outcome synchronization, and EPR hardware triggers.
\end{enumerate}

This modular five-pass separation provides the structural guarantee of correctness, allowing DQC to scale from small multi-chip prototypes to large-scale quantum datacenters.
